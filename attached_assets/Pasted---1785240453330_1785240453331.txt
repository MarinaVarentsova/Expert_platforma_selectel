Нужно улучшить карточки в разделе эксперта «Требуют действия».

Проблема:

Когда в карточке отображается действие:

- «Вас выбрали по заказу»
- «Вам согласовали дату»

эксперту непонятно, к какому именно заказу относится действие. Сейчас видны только номер заказа и данные заказчика.

Нужно добавить в такие карточки блок:

«Подробнее о заказе»

Ориентир — существующий раскрывающийся блок «Подробнее о заказе» на странице карточки заказа.

Требования:

1. Добавить раскрывающийся блок «Подробнее о заказе» в карточки action items для типов:

- эксперт выбран заказчиком;
- дата эксперта согласована заказчиком.

2. Не дублировать всю страницу заказа целиком.

Внутри блока показать компактно:

- номер заказа;
- название заказа;
- направление экспертизы;
- регион;
- срочность;
- дата создания;
- краткое описание заказа, если оно есть.

3. Внизу блока добавить кнопку:

«Открыть заказ»

По нажатию перейти на:

/requests/{requestId}

4. Если необходимые данные уже есть в объекте action item — использовать их.

Если данных нет:
- не делать отдельный запрос на каждую карточку без необходимости;
- сначала проверить, можно ли расширить существующий ответ action-items/me данными заказа;
- выбрать минимальное решение без изменения бизнес-логики.

5. Визуально использовать существующий компонент или стили блока «Подробнее о заказе» со страницы RequestDetail, чтобы интерфейс выглядел одинаково.

6. По умолчанию блок должен быть свёрнут.

7. Основные кнопки действия оставить без изменений:

- «ОК, беру в работу»;
- «Могу начать с даты»;
- «Отказаться»;
- другие существующие действия.

8. Не менять:

- статусы;
- переходы заказа;
- логику action items;
- Auth Service;
- БД без крайней необходимости;
- server.js без необходимости;
- обработчики существующих кнопок.

9. Обязательно проверить оба сценария:

Сценарий А:
- заказчик выбрал эксперта;
- у эксперта карточка «Вас выбрали»;
- раскрывается «Подробнее о заказе»;
- кнопка «Открыть заказ» ведёт на правильный requestId.

Сценарий Б:
- заказчик согласовал предложенную дату;
- у эксперта карточка «Вам согласовали дату»;
- раскрывается «Подробнее о заказе»;
- кнопка «Открыть заказ» ведёт на правильный requestId.

10. Сначала проведи аудит и покажи:

- где сейчас рендерятся карточки «Требуют действия»;
- какие поля заказа уже приходят в action item;
- можно ли переиспользовать существующий компонент «Подробнее о заказе»;
- какие файлы потребуется изменить.

После аудита не вноси изменения, пока не покажешь результат.
