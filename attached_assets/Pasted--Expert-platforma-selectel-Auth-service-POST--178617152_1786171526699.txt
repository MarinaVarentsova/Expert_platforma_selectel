Работаем ТОЛЬКО в приложении Палаты Expert_platforma_selectel.

Auth-service уже доработан:
POST /api/auth/register теперь принимает:

consent_personal_data: boolean
consent_platform_rules: boolean
consent_marketing: boolean

Задача Палаты:
передать значения ТРЁХ УЖЕ СУЩЕСТВУЮЩИХ галок регистрации в auth-service.

Никаких новых checkbox создавать не нужно.

==================================================
1. НАЙТИ ТРИ СУЩЕСТВУЮЩИЕ ГАЛКИ
==================================================

В Register.tsx найти существующие checkbox:

1. согласие на обработку персональных данных;
2. согласие с правилами/условиями платформы;
3. согласие на маркетинговые/информационные сообщения.

Не менять:
- их текст;
- дизайн;
- расположение;
- обязательность;
- текущую UX-логику.

==================================================
2. ДОБАВИТЬ ИХ В ТЕКУЩУЮ РЕГИСТРАЦИЮ
==================================================

Найти существующий вызов регистрации:

POST /api/auth/register

В текущий body добавить:

consent_personal_data: <значение первой галки>,
consent_platform_rules: <значение второй галки>,
consent_marketing: <значение третьей галки>

Использовать существующие state-переменные checkbox.

Не создавать дублирующий state.

Не менять остальные поля body.

==================================================
3. ОЖИДАЕМОЕ ПОВЕДЕНИЕ
==================================================

Если пользователь поставил:

ПД = true
Правила = true
Маркетинг = true

backend должен получить:

{
  "consent_personal_data": true,
  "consent_platform_rules": true,
  "consent_marketing": true
}

Если маркетинговая галка не поставлена:

{
  "consent_personal_data": true,
  "consent_platform_rules": true,
  "consent_marketing": false
}

Обязательные две галки должны продолжать работать так же, как сейчас.

==================================================
4. ОБРАБОТКА ОШИБКИ BACKEND
==================================================

Auth-service теперь может вернуть HTTP 400, если:

consent_personal_data != true
или
consent_platform_rules != true.

Не менять существующую frontend-валидацию.

Но убедиться, что если backend вернул ошибку регистрации, пользователь видит нормальное существующее сообщение ошибки, а не необработанный exception.

==================================================
5. НЕ ТРОГАТЬ
==================================================

Не менять:

- auth-service;
- Login;
- logout;
- forgot/reset password;
- verify;
- регистрацию профиля после auth;
- PostgreSQL;
- AI;
- matching;
- дизайн Register;
- тексты согласий;
- ссылки на документы;
- маршруты;
- Environment Variables.

Только передать три существующих boolean в register request.

==================================================
6. ПРОВЕРКИ
==================================================

Проверить:

A.
ПД=true
Правила=true
Маркетинг=true
→ request содержит true,true,true.

B.
ПД=true
Правила=true
Маркетинг=false
→ request содержит true,true,false.

C.
Без одной из двух обязательных галок существующая форма не позволяет корректно зарегистрироваться.

D.
Остальные поля регистрации передаются без изменений.

E.
build
tsc --noEmit
все существующие тесты.
