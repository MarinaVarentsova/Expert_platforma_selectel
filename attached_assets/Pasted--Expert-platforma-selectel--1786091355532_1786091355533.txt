Работаем только в репозитории Expert_platforma_selectel.

Сейчас завершаем перенос бизнес-логики со frontend на backend и приводим архитектуру к единому принципу.

Во время аудита подтверждено, что часть логики формирования status_events реализована одновременно во frontend и на backend. Из-за этого появляются дублирующиеся записи, а часть старой реализации больше не используется.

Необходимо завершить миграцию.

### Задача

1. Сделать backend единственным источником формирования status_events при выставлении рейтингов.

Для двух сценариев:

• заказчик оценивает эксперта;
• эксперт оценивает заказчика.

В обоих случаях запись в palata_status_events должна создаваться только backend одновременно с сохранением рейтинга в рамках одной транзакции.

Frontend после этого не должен самостоятельно создавать status_events.

---

2. После переноса проверить frontend.

Если функции:

- logEvent()
- logStatusEvent()

после миграции больше нигде не используются, необходимо:

• убрать их вызовы;
• убрать сами функции;
• убрать связанные импорты.

Это завершение миграции, а не изменение бизнес-логики.

---

3. После изменений подтвердить архитектуру.

Должно получиться следующее:

✓ frontend больше не создаёт записи в palata_status_events;

✓ backend полностью отвечает за регистрацию событий;

✓ одна операция пользователя создаёт одну запись в журнале событий;

✓ дубли status_events отсутствуют.

---

4. Провести аудит после изменений.

Проверить:

- остались ли любые вызовы logEvent();
- остались ли любые вызовы logStatusEvent();
- остались ли обращения к palata_status_events из frontend;
- есть ли дублирование между frontend и backend.

---

5. Ничего больше не менять.

Не затрагивать:

- AI;
- Auth;
- Matching;
- Action Items;
- процесс создания заявок;
- подбор экспертов;
- структуру базы данных;
- API контракт.

Работа касается только завершения переноса status_events.

---

6. После завершения предоставить отчёт.

В отчёте указать:

• какая логика была перенесена на backend;

• какие участки frontend стали устаревшими и были убраны;

• подтвердить, что frontend больше не создаёт status_events;

• подтвердить отсутствие дублей;

• результаты build;

• результаты tsc;

• результаты тестов;

• hash commit.
